# What Phil Strats should add next: site-level features

*November 2026. This builds on `reports/Traveler search intents and guide design.md` and doesn't repeat it. That report designed the single destination page. This one covers what sits above the destination pages.*

## The short version

Every destination page is now a full planner, but the site as a whole is still just a list of guides. Useful travel sites help people do three things across destinations:

1. **Choose between places.** 59% of travelers haven't settled on a destination when they start planning ([Expedia Group](https://partner.expediagroup.com/en-us/resources/blog/path-to-purchase-insights)).
2. **Connect places into a trip.** Two-week Philippine itineraries chain ferries, vans and short flights, and guides keep telling readers to limit themselves to two or three bases ([Backpacking Is Life](https://backpackingislife.com/2-week-philippines-itinerary/)).
3. **Prepare once for the whole country.** That means eTravel, cash, SIM, safety and transport between islands.

Phil Strats has a head start. Each guide's frontmatter already holds structured `months` (12 ratings), `budget.styles` (₱ per day), `routes`, `bestFor` and `quickFacts`, and the guide saves picks to `localStorage` under per-slug keys. Most of the recommendations below are build-time aggregations of data the site already has. That keeps them low or medium effort on a static export and lets them be visual and easy to navigate, which is what the brand is about.

Note: `src/content/` currently has 20 guides, not about 29. All of the features below scale automatically as guides are added.

### Considered and ranked lower

- **"Which island suits you?" quiz.** It serves the dreaming stage and is shareable, but the engagement claims come from vendors. The earlier report advised keeping quizzes off guide pages. If you build one, make it a 5-question page whose results deep-link to `/articles?category=…` and `/when/…`. Effort is low, so it's a reasonable bonus after #1 to #6.
- **Ferry and flight connection map.** It's useful but goes stale fast (routes change, as with the end of Manila–El Nido flights in March 2026). Fold it into #4 as data rather than a separate map.
- **Standalone currency converter.** The budget calculator already converts to USD using `usdRate`. A static site can't fetch live rates without a third-party API. Reuse the converter in #8 and #5 instead.
- **Standalone seasonal/weather overview.** This is the same thing as #1, so keep it as one page.

## Suggested build order

1. **Phase 1, aggregation pages from existing data:** `/when` (1), `/first-time` (3), `/my-trip` (5) and print CSS (9). These replace the removed Blurbs page in the nav with real utility: Home · Destinations · When to go · First time? · Newsletter, plus a "My trip" icon.
2. **Phase 2, visual navigation:** Map (2), Compare and budget (6, 8), Festivals (7).
3. **Phase 3, the differentiator:** curated island-hopping routes first, then the free-form trip builder (4).

## Three quick wins (under an hour each)

1. **Replace "Blurbs" in `NAV`** (`src/lib/site.ts`) with "When to go" pointing to a new `/when` page that renders the existing `months` data as a heatmap of all destinations by month. No new data is needed.
2. **Add a print stylesheet** (`@media print` in `globals.css`): hide the header, footer, newsletter and buttons, expand every tab and accordion panel, and add a "Print this guide" button. Readers get an offline copy for boat days with no signal.
3. **Add a "Pairs well with" / "vs" link block to each guide.** Add an optional `pairsWith: [slug]` field to frontmatter, validated like `category`, and render 1–2 cards near the top ("Coron vs El Nido →"). This links to the comparison intent before the Compare tool exists, and it's the first step toward the trip builder.

## Caveats

- Most sources for itineraries, phrases and festivals are blogs or aggregators. Festival dates and ferry legs conflict between sources and need a "verified" stamp, as in the guides.
- I found no independent data on how much people use maps or comparison tools on travel *websites*. The case rests on what leading planners build and on the intents identified in the earlier report.
- Because the brand is a mock, placeholder data is acceptable. Pages for entry and safety should still link to official sources (etravel.gov.ph, PAGASA, government travel advisories).
